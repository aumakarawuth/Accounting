## สถานการณ์ (`tests/load/classroom.js`)

- **นักเรียน** ทยอยเข้า 30 วินาทีตอนเริ่มคาบ แล้วทำงาน 4 นาที วนรอบละ ~15 วินาที: พิมพ์ร่าง 3 จังหวะ (presence) → ผ่านรายการ → เปิดงบทดลอง/แยกประเภท/งบการเงินเป็นบางรอบ
  - 10% **กดซ้ำ**: ส่งรายการเดียวกันสองคำขอพร้อมกันด้วย idempotency key เดียวกัน
  - 10% **เน็ตหลุด**: คำขอแรกหมดเวลาฝั่ง client (5 ms) แล้วส่งใหม่ด้วย key เดิม
  - 30% **มือถือช้า**: คิดนานกว่า (k6 จำลองแบนด์วิดท์/latency ไม่ได้ — ดูข้อจำกัด)
  - ผ่านรายการเฉลี่ยคนละครั้งทุก ~16 วินาที **หนักกว่าห้องเรียนจริงหลายเท่า** (จริงน่าจะคนละ 1–2 นาที)
- **ครู** ทุกห้องดูแดชบอร์ดทุก 5 วินาที และดูสดนักเรียนแบบสุ่ม (เริ่ม → ดึงข้อมูล 3 ครั้ง → ping → หยุด)
- **SSE** (`sse-holders.mjs`) เปิดช่อง realtime ของนักเรียนทุกคนค้างไว้ทั้งรอบ (k6 ไม่รองรับ SSE)
- หลังจบ `verify.mjs` ตรวจฐานข้อมูลทุกบริษัท

## สิ่งที่แก้จากการทดสอบ

1. **จำกัดอัตราต่อ IP ทำให้ทั้งโรงเรียนเข้าไม่ได้** — รอบแรกคำขอล้ม 78% (429) เพราะทุกคนมาจาก IP เดียว (เหมือนโรงเรียนที่ออกเน็ตผ่าน NAT)
   - ย้ายตัวจำกัดหลักเป็น **ต่อผู้ใช้** 600 คำขอ/นาที (`REQUESTS_PER_USER_PER_MINUTE`)
   - ต่อ IP เหลือไว้กันน้ำท่วม 60,000/นาที (`REQUESTS_PER_IP_PER_MINUTE`)
   - ล็อกอินต่อ IP 300 → 1,200/นาที (`LOGIN_PER_IP_PER_MINUTE`) — การเดารหัสยังถูกจำกัดด้วยล็อกต่อบัญชี (ผิด 5 ครั้ง) และเพดานล็อกอิน**ผิด**ต่อ IP 300 ครั้ง/15 นาที เหมือนเดิม
   - แนวทางตั้งค่า: `LOGIN_PER_IP_PER_MINUTE` ≥ จำนวนนักเรียนที่อาจเข้าพร้อมกันจาก IP เดียว × 1.5
2. **คำขอ JSON ว่าง/เสียได้ 500** — error ฝั่งคำขอของ Fastify ตอนนี้ได้ 400 `invalid` (มีเทสต์)

## ข้อจำกัด (ต้องทำในเฟสกลางบนเซิร์ฟเวอร์จริง)

- k6 กับระบบอยู่เครื่องเดียวกัน แย่ง CPU กันเอง และไม่มีเวลาเดินทางของเครือข่าย
- ไม่ได้ผ่าน Caddy + Next.js + TLS (หน้าเว็บ SSR และ rewrite `/api` ยังไม่ได้วัดภายใต้โหลด)
- ไม่มี PgBouncer (แผนกำหนด transaction pooling) และ API มี process เดียว — ถ้าหลาย process ต้องย้าย rate limit และ realtime ไป Redis
- จำลองเน็ตมือถือช้า/สัญญาณหลุดจริงไม่ได้ด้วย k6 → ใช้ `tc netem` บนเซิร์ฟเวอร์ทดสอบ และทดสอบบนอุปกรณ์จริง (iPhone Safari, Android Chrome, iPad) ตาม PLAN.md ข้อ 8
- ข้อมูลเริ่มจากฐานว่าง ไม่ได้วัดตอนตารางใหญ่ขึ้น (หลายภาคเรียน) — ควรทดสอบซ้ำด้วยข้อมูลสะสมระดับปี

## วิธีรัน

```sh
# k6: ใช้ไบนารีทางการ หรือ build เอง: go install go.k6.io/k6@latest
tests/load/setup.sh 500                       # สร้างฐาน accounting_load + นักเรียน 500 คน
cd apps/api && pnpm build && DATABASE_URL=postgres://app_load:app_load@localhost/accounting_load \
  COOKIE_SECURE=false WEB_ORIGIN=http://localhost:3000 NODE_ENV=production node dist/server.js &
node tests/load/sse-holders.mjs http://127.0.0.1:4000 500 380 &   # SSE ค้าง
k6 run -e ROLE=teachers tests/load/classroom.js &                  # ครู
k6 run -e ROLE=students tests/load/classroom.js                    # นักเรียน (SHORT=1 = รอบสั้น)
node tests/load/verify.mjs postgres://postgres@localhost/accounting_load <entries_confirmed จาก k6>
k6 run tests/load/login-burst.js                                   # กดเข้าพร้อมกันเป๊ะ
```
