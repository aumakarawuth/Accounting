## 1. ชุดโจทย์ (ครู)

| ตาราง | เนื้อหา | ใครเห็น |
|---|---|---|
| `acc.exercise_sets` | ชื่อชุด, ชื่อบริษัทตั้งต้น, คำอธิบาย, `version` | ครูเจ้าของชุด |
| `acc.exercise_items` | ข้อที่ (1..n), วันที่, ข้อความรายการค้า, คะแนน | ครูเจ้าของชุด (นักเรียนเห็นผ่าน `acc.assignment_view` ตามเวลาเท่านั้น) |
| `acc.exercise_answer_lines` | เฉลย: รหัสบัญชี เดบิต/เครดิต ต่อข้อ | ครูเจ้าของชุดเท่านั้น (นักเรียนไม่มี policy เลย) |

- เขียนผ่าน `acc.save_exercise_set(id, version, payload)` เท่านั้น (ทั้งชุดในครั้งเดียว + optimistic locking)
- ตรวจตอนบันทึก: 1–200 ข้อ, ข้อละ 2–20 บรรทัด, เดบิต = เครดิต, ทศนิยม ≤ 2, รหัสบัญชีต้องมีในผังตั้งต้น
  (`acc.coa_template`) เพราะบริษัทของนักเรียนเริ่มจากผังนี้, คะแนนรวม ≤ 999.99
- แก้เฉลยหลังมอบหมายแล้วได้ (เช่น เฉลยพิมพ์ผิด) คะแนนคิดใหม่จากเฉลยล่าสุดทันที · ลบชุดได้เมื่อยังไม่เคยมอบหมาย

## 2. มอบหมาย (`acc.assignments`)

ครูมอบหมายชุดโจทย์ให้ห้องที่สอน → ระบบเปิดบริษัทให้นักเรียนทุกคนในห้อง (คนละชุดบัญชี เจ้าของคือนักเรียน)
`companies.assignment_id` ผูกบริษัทกับงาน (1 คน 1 บริษัทต่องาน) นักเรียนที่เข้าห้องทีหลังกด "เปิดบริษัทให้คนที่ยังไม่มี" ซ้ำได้

| โหมด | บริษัท | ล็อก |
|---|---|---|
| ฝึกหัด (`practice`) | `mode = practice` | ล็อกเมื่อครูปิดงาน |
| ส่งงาน (`submit`) | `mode = submit` + วงจรส่งตรวจเดิม (คะแนนเต็ม = คะแนนรวมของชุด) | ส่งตรวจแล้ว / ครูปิดงาน |
| สอบ (`exam`) | `mode = submit` + จับเวลา | ยังไม่กดเริ่ม · หมดเวลา · ครูปิดสอบ · ส่งแล้ว |
| สาธิต (`demo`) | บริษัทของครูเอง ไม่ผูกห้อง | — |

ตั้งค่าตอนมอบหมาย (แก้ทีหลังได้ ยกเว้นโหมด):
- **การแสดงผลให้นักเรียน** `feedback`: `none` (ครูเห็นคนเดียว) · `score` (คะแนนรวม) · `items` (ข้อไหนถูก/ผิด) · `answers` (+ เฉลยและบรรทัดที่ต่าง)
- **เมื่อไร** `reveal`: `anytime` (กดตรวจเองได้ตลอด เหมาะกับฝึกหัด) · `after_submit` (หลังส่งตรวจ) · `after_release` (เมื่อครูกด "เปิดเฉลย")
- **ตรวจวันที่** `check_date` (ค่าเริ่มต้น: ตรวจ) · ชื่อบริษัท (ห้ามซ้ำกับบริษัทที่มีอยู่ในห้อง)
- สอบ: บังคับ `reveal = after_release` · ต้องมีเวลาสอบ (นาที) · เปิด/ปิดรับได้ตามเวลา (`opens_at`/`closes_at` ไม่บังคับ)

## 3. ตรวจอัตโนมัติ

ฟังก์ชันบริสุทธิ์ `app.grade_match(items, entries, check_date)` (ทดสอบตรงด้วยข้อมูลสุ่มเทียบกับตัวอ้างอิง TypeScript)

1. **รายการที่นับ** = รายการในสมุดรายวัน (ทุกเอกสาร) ที่ไม่ใช่การกลับรายการและไม่ถูกกลับรายการ
2. **ทำให้เป็นรูปเดียวกัน**: รวมยอดสุทธิต่อรหัสบัญชีในรายการเดียว (เดบิต − เครดิต) ทิ้งบัญชีที่สุทธิเป็นศูนย์
   แล้วเรียงเป็นชุด `รหัส|D/C|จำนวน` จึง **ไม่สนลำดับบรรทัด** และแยกบรรทัดบัญชีเดียวกันได้ (เช่น เงินสด 600 + 400 = 1,000)
3. **จับคู่ทีละข้อ** (ข้อน้อยไปมาก, รายการตามวันที่แล้วเลขที่ แต่ละรายการใช้ได้ข้อเดียว):
   ก. ชุดบรรทัดตรง + วันที่ตรง → `correct` ได้คะแนนเต็ม
   ข. ชุดบรรทัดตรงแต่วันที่ไม่ตรง → `date` (0 คะแนน บอกว่าวันที่ผิด) — ถ้าปิดการตรวจวันที่ ข้อ ก. ไม่ดูวันที่
   ค. ไม่ตรง: เลือกรายการวันเดียวกันที่บรรทัดตรงมากที่สุด (อย่างน้อย 1) → `wrong` พร้อมบรรทัดที่ขาด/เกิน
   ง. ไม่มีเลย → `missing`
4. รายการที่ไม่ถูกจับกับข้อใด = **รายการเกิน** (แสดงให้ครู ไม่หักคะแนน)

คะแนน = ผลรวมคะแนนข้อที่ `correct` · ครูยังให้คะแนนจริงผ่านปุ่ม "ให้ผ่าน" เดิม (ระบบเติมคะแนนอัตโนมัติให้เป็นค่าเริ่มต้น)

## 4. สิทธิ์และการซ่อนเฉลย

- นักเรียนไม่มี policy บน `exercise_*` และ `assignments` เลย ข้อมูลทั้งหมดผ่าน `acc.assignment_view(company)`
  (security definer) ซึ่งตัดตามเวลา: ข้อความโจทย์เห็นเมื่องานเปิด (สอบ: หลังกดเริ่ม) · ผลตามตาราง `feedback × reveal`
  · เฉลยเห็นเฉพาะระดับ `answers` และถึงเวลาแล้ว · สอบ = หลังครูเปิดเฉลยเท่านั้น
- ครูเห็นทุกอย่างของงานที่ตัวเองสร้าง (ห้องตัวเอง) · ครูห้องอื่น/นักเรียนคนอื่น = ไม่พบ
- `app.company_locked` เพิ่มเหตุผลล็อกจากงาน (ยังไม่เปิด, สอบยังไม่เริ่ม, หมดเวลา, ปิดงาน) ใช้ trigger เดิมทุกเส้นทางเขียน
- เหตุการณ์ของงาน (`acc.assignment_events`: มอบหมาย เริ่มสอบ เพิ่มเวลา เปิดเฉลย ปิด) แก้/ลบไม่ได้

## 5. โหมดสอบ

- นักเรียนกด "เริ่มสอบ" → `acc.start_exam` บันทึกเวลาเริ่ม หมดเวลา = เริ่ม + นาทีที่กำหนด (ไม่เกินเวลาปิดรับ)
  และเพิกถอนเซสชันอื่นของนักเรียน (1 เซสชันต่อคน) ล็อกอินใหม่ระหว่างสอบก็เตะเครื่องเก่าออก
- นาฬิกานับถอยหลังติดใต้แถบบน (ไม่ใช่ popup) เวลาจริงตัดสินที่ DB (`now()`) ไม่เชื่อนาฬิกาเครื่อง
- หมดเวลา: DB ปฏิเสธการลงรายการทุกเส้นทาง (ACC10) ผลคิดจากรายการที่ลงไว้ก่อนหมดเวลา
- ครู: ปิดสอบทันที · เพิ่มเวลา (รายคนหรือทั้งห้อง) · เปิดเฉลย · ส่งออกคะแนน

## 6. โหมดสาธิต

- ครูสร้างบริษัทสาธิตของตัวเองจากชุดโจทย์ (หรือบริษัทเปล่า) หน้าบริษัทขยายตัวอักษร (ปกติ/ใหญ่/ใหญ่มาก จำในเครื่อง)
- หน้า "งานของฉัน" แสดงโจทย์พร้อมเฉลยให้ครู + ปุ่ม "ลงรายการตามเฉลย" (เปิดสมุดรายวันที่เติมบรรทัดให้แล้ว ครูกดผ่านรายการเอง)

## 7. รายงาน PDF / Excel

| report | เนื้อหา | query |
|---|---|---|
| `trial-balance` | งบทดลอง ณ สิ้นเดือน | `month` |
| `ledger` | แยกประเภททุกบัญชีที่เคลื่อนไหวในเดือน | `month` |
| `statements` | งบกำไรขาดทุน + งบแสดงฐานะการเงิน | `month`, `scope` |
| `worksheet` | กระดาษทำการ 6/8/10 ช่อง | `month`, `format` |
| `scores` | คะแนนรายคน + รายข้อ | — |

- route ของเว็บ (`apps/web/app/export/...`) ดึง JSON จาก API ชุดเดียวกับหน้าจอด้วยเซสชันของผู้ขอ (สิทธิ์เท่าหน้าจอ) แล้วสร้างไฟล์
  ที่ `apps/web/lib/export/` หัวตารางจาก `i18n/th.ts` · SQL ของรายงานรวมไว้ที่ `apps/api/src/reports.ts` · เงินเป็นสตริงตลอดทาง ไม่ผ่าน float
- URL: `/export/company/<id>/<report>.<pdf|xlsx>?month=…` และ `/export/assignment/<id>/scores.<pdf|xlsx>`
- PDF: `pdfkit` ฝังฟอนต์ IBM Plex Sans Thai Looped (OFL) ตัดบรรทัดภาษาไทยด้วย `Intl.Segmenter` จัดตำแหน่งสระ/วรรณยุกต์ด้วย GPOS ของฟอนต์
- Excel: เขียน .xlsx เอง (XML + zip ด้วย `node:zlib`) ไม่มี dependency เพิ่ม ตัวเลขเป็นตัวเลขจริง (รูปแบบ `#,##0.00`)
  ข้อความเป็น inline string (ไม่ถูกตีความเป็นสูตร) ฟอนต์ Tahoma (มีทุกเครื่อง รองรับภาษาไทย)
- ชื่อไฟล์ภาษาไทยส่งแบบ `filename*=UTF-8''…` (กัน header injection)
