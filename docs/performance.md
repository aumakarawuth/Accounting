# ความเร็วของหน้าเว็บและการประมวลผลข้อมูล

วัดเมื่อ 10 พ.ย. 2569 บนเครื่องพัฒนา (Postgres 16 + API + `next start` เครื่องเดียว) ด้วยบริษัททดสอบที่มี **3,000 รายการบัญชี**
ตลอด 12 เดือน (250 รายการต่อเดือน มากกว่างานนักเรียนจริงหลายเท่า) วัดด้วย Chromium จอมือถือ ค่ามัธยฐาน 3 ครั้ง

## สิ่งที่พบ

1. **RLS เรียกฟังก์ชันทุกแถว (ตัวการหลัก)** policy อ่านทุกตารางบัญชีเป็น `using (app.can_read_company(company_id))`
   Postgres เรียกฟังก์ชันนี้ 1 ครั้งต่อแถวที่อ่าน: นับรายการ 3,000 แถว = เรียก 3,000 ครั้ง (`/periods` 153 ms, กระดาษทำการ 100 ms)
   เวลาโตตามจำนวนรายการของบริษัท ไม่ใช่จำนวนที่แสดง
2. **ไปกลับฐานข้อมูล 6 รอบต่อคำขอ API** (ตรวจเซสชัน, `begin`, `set_config`, ตรวจสิทธิ์, คำสั่งหลัก, `commit`)
   บนเครื่องเดียวกันแทบไม่มีผล แต่บน Vercel → Supabase ทุกรอบมีค่าเครือข่าย
3. **บน Vercel หน้าเดียวเรียก API เดิมซ้ำ** layout ของบริษัทกับหน้าลูกต่างเรียก `/companies/:id` (และ `/auth/me`)
   บน self-host Next จำผล `fetch` ซ้ำให้เอง แต่บน Vercel API ฝังในเว็บ (`inject`) ไม่ผ่าน `fetch` จึงไม่ถูกจำ
   และ layout รอผู้ใช้เสร็จก่อนค่อยดึงบริษัท (รอทีละคำขอ)

## ที่ยังไม่ได้แก้ (วัดแล้ว ผลน้อยหรือแลกกับสิ่งอื่น)

- **ข้อความไทยทั้งไฟล์ `i18n/th.ts` (~114 KB, บีบอัดแล้วราว 20 KB) ติดไปทุกหน้า** เพราะ client component 49 ตัว import ทั้งไฟล์
  แยกต่อหน้าได้แต่ขัดกติกา "ข้อความหน้าจออยู่ที่ th.ts" ต้องเปลี่ยนเป็นส่งข้อความจาก server component ลงมา (งานใหญ่) ไฟล์ถูก cache ถาวรหลังเปิดครั้งแรก
- **หน้าสมุดรายวันเดือนที่มี 200 รายการ HTML 549 KB (บีบอัดแล้ว 46 KB)** เพราะมีทั้งตาราง (จอใหญ่) และรายการ (มือถือ) ในหน้าเดียว
  งานนักเรียนจริงไม่กี่สิบรายการต่อเดือน · หมายเหตุ: API ส่งไม่เกิน 200 รายการต่อเดือน (เดือนที่เกินจะไม่แสดงรายการเก่าสุด)
- JS ของ React/Next ราว 435 KB (บีบอัด ~140 KB) และฟอนต์ ~130 KB: ขนาดปกติ ถูก cache ถาวร (`immutable`)
- advisor ของ Supabase เรื่อง foreign key ไม่มี index (62 ตัว ส่วนใหญ่คอลัมน์ `created_by`/รายการที่ไม่ได้ค้น): ยังไม่จำเป็นที่ขนาดข้อมูลนี้
- cold start ของ API บน Vercel ~0.2 วินาที (โหลดโค้ด + เชื่อมฐานข้อมูลครั้งแรก) เกิดเมื่อไม่มีคนใช้สักพัก

## หมายเหตุหลังเปิด CSP แบบ nonce (10 พ.ย. 2569)

ทุกหน้าเรนเดอร์ตอนมีคำขอ (`app/layout.tsx` เรียก `connection()`) เพราะ nonce ต้องใหม่ทุกคำขอ เดิมหน้าล็อกอิน/นโยบายเป็นหน้า static ที่ CDN cache ได้
วัดในเครื่อง TTFB หน้าล็อกอินจาก ~3 ms (static) เป็น ~6 ms (มัธยฐาน 5 ครั้ง) แลกกับการเลิก `'unsafe-inline'` (`docs/owasp-top10.md`)
